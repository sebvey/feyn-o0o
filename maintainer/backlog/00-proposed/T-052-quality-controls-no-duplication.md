# T-052 : Éviter le doublon entre les règles du cours et leurs contrôles

- **Créé le** : 2026-10-24
- **Constat** : T-050h prévoit un fichier de contrôles de qualité du cours (`maintainer/quality/course-quality-controls.md`). Dans sa première forme, chaque contrôle écrit en entier son critère pour qu'un agent l'applique sans ouvrir d'autre fichier ; or le même critère est déjà écrit dans la règle source (gabarit de concept, `CLAUDE.md`, ADR, `plan.md`, fil rouge). Une règle écrite deux fois dérive : le mainteneur ne l'accepte pas (demande du 2026-10-24). La contrainte opposée est qu'un agent ne doit pas charger une dizaine de fichiers épars pour appliquer quelques lignes de règles. `CLAUDE.md` est de plus chargé à chaque session de cours : on n'y ajoute pas de règle de maintenance.
- **À faire** : étudier la meilleure manière de garder une seule version de chaque règle sans éparpiller la lecture, et décider. Ce qu'il faut établir : quelles règles servent le prof à l'exécution (elles restent à leur place) et lesquelles ne servent qu'à contrôler (elles peuvent vivre dans le fichier de contrôles) ; si la règle source doit rester le gabarit, les ADR et `CLAUDE.md`, ou être déplacée ; comment un agent obtient en une lecture les règles qui touchent ses fichiers ; comment une dérive se détecte ; ce que coûte chaque option en maintenance. Piste du mainteneur et de l'agent, à confronter à d'autres : une vue assemblée par script à partir des sources, jamais commitée, avec détection des références cassées et des règles modifiées. Mettre à jour T-050h avec la décision ; un ADR si elle passe la règle de `maintenance` (§4).
- **Fini quand** : la manière de supprimer le doublon est décidée par le mainteneur, avec les options écartées ; T-050h est mis à jour en conséquence.
